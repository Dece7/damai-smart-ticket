# 约束大模型输出格式

> 让 LLM 稳定输出标准 JSON 是实际工程开发中的一大重点问题，单靠 Prompt 约束不够，需要多层保障。

---

## 一、为什么需要结构化输出

Agent 开发中很多场景**要求 LLM 返回标准 JSON**，因为输出要被代码消费：

| 场景 | 示例 |
|------|------|
| **Function Calling** | `{"name": "search_program", "arguments": {"city": "北京"}}` |
| **意图分类** | `{"intent": "ticket", "confidence": 0.95}` |
| **LLM Judge 评分** | `{"relevance": 5, "faithfulness": 5, "completeness": 4}` |
| **查询改写** | `{"rewritten": "退票政策", "original": "咋退"}` |
| **数据提取** | `{"date": "明天", "city": "北京", "actor": "周杰伦"}` |
| **多步骤规划** | `{"steps": ["查节目", "查票档", "下单"]}` |
| **摘要提取** | `{"topic": "退票", "key_points": ["48小时", "原路退回"]}` |

---

## 二、单靠 Prompt 的问题

```
Prompt: "请输出 JSON 格式：{"intent": "ticket"}"

LLM 可能输出：
  ✅ {"intent": "ticket"}                                    ← 正确
  ❌ 好的，我来分析一下：{"intent": "ticket"}                   ← 前面多了废话
  ❌ {"intent": "ticket",}                                   ← 多了逗号
  ❌ {"intent": ticket}                                      ← 少了引号
  ❌ ```json\n{"intent": "ticket"}\n```                      ← 包在代码块里
```

**LLM 不保证 100% 输出标准 JSON**，尤其在流式生成时更容易出格式问题。

---

## 三、五种约束手段

### 方案一：💥Prompt 约束（基础，必须做）

```
请只输出 JSON，不要添加任何解释或多余文字。
输出格式：{"intent": "ticket", "confidence": 0.9}
```

**效果**：能解决大部分问题，但不保证 100%。

### 方案二：💥输出解析 + 容错（工程必备）

```python
content = response.content.strip()

# 去掉代码块标记
if content.startswith("```json"):
    content = content[7:-3].strip()

# 直接解析
if content.startswith("{") and content.endswith("}"):
    result = json.loads(content)
else:
    # 正则提取 JSON
    match = re.search(r'\{.*\}', content, re.DOTALL)
    if match:
        result = json.loads(match.group())
```

### 方案三：💥LangChain StructuredOutput（推荐）

```python
from langchain_core.output_parsers import JsonOutputParser
from pydantic import BaseModel

class IntentResult(BaseModel):
    intent: str
    confidence: float

parser = JsonOutputParser(pydantic_object=IntentResult)

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是意图分类器。{format_instructions}"),
    ("human", "{question}")
]).partial(format_instructions=parser.get_format_instructions())

chain = prompt | llm | parser
result = chain.invoke({"question": "退票政策"})
# result = {"intent": "knowledge", "confidence": 0.95}
```

**自动注入 JSON Schema 到 Prompt + 自动解析 + 自动重试。**

### 方案四：💥原生 JSON Mode（模型级支持）

```python
llm = ChatOpenAI(
    model="mimo-v2.5",
    model_kwargs={"response_format": {"type": "json_object"}}
)
# 强制输出合法 JSON
```

**最可靠**，但不是所有模型都支持。

### 方案五：💥输出校验 + 重试

```python
for attempt in range(3):
    response = llm.invoke(messages)
    try:
        result = json.loads(response.content)
        if validate_schema(result):  # 校验字段是否齐全
            return result
    except json.JSONDecodeError:
        continue  # 解析失败，重试
```

## 四、五种方案对比

| 方案 | 可靠性 | 复杂度 | 适用场景 |
|------|--------|--------|---------|
| Prompt 约束 | ⭐⭐ | 低 | 所有场景（基础） |
| 输出解析 + 容错 | ⭐⭐⭐ | 低 | 工程必备 |
| StructuredOutput | ⭐⭐⭐⭐ | 中 | LangChain 项目 |
| 原生 JSON Mode | ⭐⭐⭐⭐⭐ | 低 | 模型支持时 |
| 校验 + 重试 | ⭐⭐⭐⭐ | 中 | 高可靠场景 |

**不是选一种，而是叠加使用。**

---

## 五、企业级最佳实践

```
Prompt 约束（基础）
  ↓
原生 JSON Mode（如果模型支持）
  ↓
JsonOutputParser 自动解析
  ↓
容错处理（去代码块、正则提取）
  ↓
Schema 校验（字段是否齐全、类型是否正确）
  ↓
失败重试（最多 3 次）
```

## 六、本项目现状

```python
# 意图分类：Prompt 约束 + 正则提取
"只输出一个小写的分类词：ticket / knowledge / both / chat"
for valid in ("ticket", "knowledge", "both", "chat"):
    if valid in content:
        intent = valid
```

只用了 Prompt + 正则，没有用 JsonOutputParser 或 JSON Mode。够用但不够稳。

## 七、面试高频问题

| 问题 | 回答要点 |
|------|---------|
| 怎么让 LLM 输出标准 JSON？ | 多层保障：Prompt 约束 + JSON Mode + Parser + 容错 + 重试 |
| 单靠 Prompt 够吗？ | 不够，LLM 输出不稳定，需要工程层面兜底 |
| JsonOutputParser 是什么？ | LangChain 的输出解析器，自动注入 Schema + 自动解析 |
| JSON Mode 是什么？ | 模型级强制输出合法 JSON，最可靠但不是所有模型支持 |
| 输出格式错了怎么办？ | 容错处理：去代码块标记、正则提取 JSON、Schema 校验、失败重试 |

---

## 八、面试话术

> "**让 LLM 稳定输出 JSON，单靠 Prompt 不够。企业级做法是多层保障：Prompt 约束（基础）+ 原生 JSON Mode（模型级）+ JsonOutputParser 自动解析（框架级）+ 容错处理（去代码块、正则提取）+ Schema 校验 + 失败重试。当前项目用 Prompt + 正则提取，够用但不够稳。**"
