# RAG 评估体系

> RAG 效果怎么量化？怎么回答面试官"优化效果提升了多少"？

---

## 一、RAG 两个大阶段

```
  💥检索阶段                  💥生成阶段
找到正确的文档    ─────→    基于文档生成准确的回答
   Recall    高              Accuracy   高
   Precision 高              LLM Judge  高
```

**检索是基础**。检索不到正确文档，生成再好也是"编造"。优化顺序：先优化检索，再优化生成。

**定位问题的方法**：
- 回答错了但检索到了正确文档 → **生成问题**（Prompt、模型能力）
- 回答错了因为没检索到正确文档 → **检索问题**（Embedding、切分、检索策略）
- 回答对了但不完整 → **检索覆盖不足**（Recall 低）或**生成遗漏**（Prompt 约束）

## 二、检索阶段指标

### 1. 💥Recall（召回率）— "找得到"

**定义**：在所有相关文档中，检索到了多少？

```
知识库里有 3 篇文档和"退票"相关
检索返回了 5 篇，其中包含 2 篇相关文档
Recall = 2/3 = 66.7%
```

**公式**：`Recall = 检索到的相关文档数 / 所有相关文档数`

**通俗理解**：该找的都找到了吗？漏了几个？

### 2. 💥Precision（精确率）— "找得准"

**定义**：检索返回的文档中，有多少是真正相关的？

```
检索返回了 5 篇文档
其中 3 篇是真正相关的
Precision = 3/5 = 60%
```

**公式**：`Precision = 检索到的相关文档数 / 检索返回的总文档数`

**通俗理解**：找到的东西里有多少是靠谱的？掺了多少噪音？

### 3. Recall vs Precision 的关系

```
场景 A：返回 100 篇文档
  → Recall 很高（大概率覆盖了所有相关文档）
  → Precision 很低（大部分是噪音）

场景 B：返回 1 篇文档
  → Precision 很高（如果命中了就是 100%）
  → Recall 很低（大概率漏了很多相关文档）
```

**成熟团队同时看两个指标**，通常用 F1 分数综合：

```
F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

### 4. 💥Recall@K

**定义**：返回 Top-K 个结果时的召回率。

```
Recall@5 = 在返回的前 5 个结果中，命中了多少相关文档？
Recall@10 = 在返回的前 10 个结果中，命中了多少相关文档？
```

**RAG 场景通常看 Recall@K**，因为更关心"该找的都找到"。K 一般取 3、5、10。

**本项目数据**：来源命中率 @5 = 100%（DashScope Embedding + Parent-Child 分块，65 条测试用例）

### 5. 💥MRR（Mean Reciprocal Rank）

**定义**：第一个相关结果排在第几位。越靠前越好。

```
相关文档排在第 1 位 → MRR = 1/1 = 1.0
相关文档排在第 3 位 → MRR = 1/3 = 0.33
相关文档排在第 5 位 → MRR = 1/5 = 0.2
```

**通俗理解**：用户翻几屏才能找到答案？

## 三、生成阶段指标

### 6. 💥LLM Judge — "回答好不好"

**定义**：用另一个 LLM 来评判生成的回答质量。

**两种模式**：

| 模式 | 需要标准答案？ | 做法 | 可靠性 |
|------|-------------|------|--------|
| 有标准答案 | ✅ 需要人工标注 | 比对生成回答和标准答案 | 高，但成本高 |
| 无标准答案 | ❌ 不需要 | 比对生成回答和检索文档 | 较高，更常用 |

**Judge 怎么判断**：不是凭空判断，而是拿回答和检索文档做比对。

```
相关性：回答是否回应了用户问题？    → 看问题和回答的匹配度
忠实度：回答是否基于检索文档？      → 看回答和文档的吻合度
完整性：回答是否覆盖了文档的关键信息？ → 看回答和文档的覆盖度
```

**评判维度**：

| 维度 | 问什么 | 对应问题 |
|------|--------|---------|
| **相关性（Relevance）** | 回答是否回答了用户的问题？ | 答非所问 |
| **忠实度（Faithfulness）** | 回答是否基于检索到的文档？ | 编造信息（幻觉） |
| **完整性（Completeness）** | 回答是否覆盖了所有相关信息？ | 遗漏信息 |

**评分方式**（1-5 分）：

```
问题: "退票政策是什么？"
检索到的文档: [退票政策文档]
生成的回答: "退票需要在演出前48小时申请..."

LLM Judge:
- 相关性: 5分（回答了用户的问题）
- 忠实度: 5分（没有编造，基于文档）
- 完整性: 4分（覆盖了主要信息，但遗漏了条件退的细节）
```

**Judge 自己会不会有幻觉**：会。企业级降低风险的方法：
- 用更强的模型做 Judge（如用 Claude 评判 GPT 的回答）
- 多个 Judge 取共识（3 个 Judge 打分取平均）
- 结构化输出（强制 JSON 格式）
- 人工抽检（定期验证 Judge 准确性）

**本项目实现**：用 Mimo 做 Judge，无标准答案模式，拿检索文档和生成回答比对。综合评分 4.9/5。

### 7. 💥幻觉率（Hallucination Rate）

**定义**：回答中有多少内容是检索文档中没有的。

```
回答: "退票需要在演出前48小时申请，票款7个工作日退回"
检索文档: "退票需要在演出前48小时申请，票款3个工作日退回"

幻觉: "7个工作日"（文档写的是 3 个工作日）
幻觉率 = 1/2 = 50%
```

### 8. 💥答案正确率（Accuracy）

**定义**：回答是否正确回答了用户的问题。

```
问题: "退票后多久退款？"
标准答案: "3个工作日内"
模型回答: "3个工作日内按原付款路径退回"
Accuracy = 正确 ✅

问题: "退票后多久退款？"
模型回答: "不支持退票"
Accuracy = 错误 ❌
```

## 四、评估方法论

### 评估层次

| 层次 | 测什么 | 怎么测 | 本项目 |
|------|--------|--------|--------|
| **检索质量** | Recall@K, Precision, MRR | 标注数据集 + 自动计算 | ✅ Recall@5=100%, Precision@5=55.7%, MRR=0.992 |
| **生成质量** | 相关性、忠实度、完整性 | LLM Judge 评分 | ✅ 综合 4.9/5，忠实度 5.0（无幻觉） |
| **端到端** | 成功率、关键词命中率 | 真实查询 + 自动检查 | ✅ 成功率 100%，关键词命中 98.5% |
| **用户满意度** | 点赞/点踩、人工评分 | 前端埋点 | ❌ 未做 |

### 标注数据集格式

```json
[
  {
    "question": "退票政策是什么",
    "expected_docs": ["节目取消和退票-相关问题与回答.md"],
    "expected_answer_contains": ["退票", "演出详情页"],
    "expected_intent": "knowledge"
  },
  {
    "question": "帮我查北京演唱会",
    "expected_docs": [],
    "expected_answer_contains": ["演唱会", "北京"],
    "expected_intent": "ticket"
  }
]
```

### A/B 测试框架

```
基线（HashEmbedding）    实验组（DashScope + Parent-Child）
  ↓                       ↓
同一组测试问题 ───→ 分别跑 ───→ 对比指标
  ↓                       ↓
Recall@5 = 23.6%    Recall@5 = 100%   → +76.4%
```

## 五、面试高频问题

| 问题 | 回答要点 |
|------|---------|
| RAG 效果怎么评估？ | 三个层面：检索质量（Recall/Precision）、生成质量（LLM Judge）、端到端（成功率） |
| Recall 和 Precision 的区别？ | Recall = 该找的都找到了吗；Precision = 找到的东西准不准 |
| RAG 场景更看重哪个？ | 通常更看重 Recall@K，因为漏掉相关文档比多返回噪音更严重 |
| 怎么检测幻觉？ | 对比回答和检索文档的内容，看有没有文档中没有的信息 |
| LLM Judge 怎么做？ | 用另一个 LLM 从相关性、忠实度、完整性三个维度打分 |
| 优化效果怎么量化？ | A/B 测试：同一组问题分别跑优化前后，对比 Recall/Precision/成功率 |
| 没有标注数据怎么办？ | 先用 LLM 自动生成标注（silver label），再人工校验（gold label） |
