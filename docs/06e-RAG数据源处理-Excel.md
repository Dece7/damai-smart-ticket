# RAG 复杂数据源处理 — Excel

> 向量库擅长找相关，但 Excel 问题经常要求算正确。Excel 不是文档，是数据资产。

---

## 一、做 RAG，最容易踩坑的文件是什么？

**面试提问**：RAG 处理 Excel 数据有什么坑？

💥**优质回答**💥：
> 不是 PDF，也不是 Word，而是 Excel。因为很多人直接走老套路：解析文本 → 切 chunk → 向量化 → 丢进向量库 → 开始猜。听起来像完成了 RAG，实际上只是把表格拍扁了。

```
❌ 常见错误做法：
  Excel → 转文本 → 切 chunk → Embedding → 向量库 → 检索 → 猜答案

  用户问："哪个产品销售额最高"
  → 检索到几行相关数据
  → 没有全局计算能力
  → Agent 只能靠猜
```

---



## 二、直接进向量库，问题出在哪？

| 问题 | 说明 |
|------|------|
| 检索到相关行 | 用户问"哪个产品销售额最高"，Agent 只找回几行相关数据 |
| 没有全局计算 | 最高、最低、总数、增长率，需要全表筛选和统计，不是语义相似 |
| 结果只能靠猜 | 用户问"3 月华东区为什么下降"，检索到词，不代表算出了下降幅度 |

**本质区别**：

```
向量检索：找"相关"的文本片段（语义相似度排序）
Excel 问题：要"精确"的计算结果（筛选→统计→排序→计算）

"相关"≠"正确"
```

---



## 三、Excel 到底该不该进向量库？

**❇️答案不是不能进，而是不能原样进。**

Excel 里有两类信息，处理方式完全不同：

| 类型 | 内容 | 适合去哪 | 示例 |
|------|------|---------|------|
| **语义信息** | 字段说明、业务口径、备注、异常原因 | 向量库 | "销售额字段指含税收入" |
| **结构化数据** | 订单明细、金额、日期、地区、产品 | 数据库 / DataFrame | "3 月华东区销售额 120 万" |

```
用户问："销售额字段是什么意思？" 
→ 找解释 → 向量检索
用户问："哪个产品销售额最高？"    → 要计算 → 结构化查询
用户问："3 月华东区为什么下降？"  → 先算再找 → 计算 + 语义检索
```

**面试话术**：
> "Excel 不是不能进向量库，而是不能原样进。语义信息（字段说明、口径、备注）适合进向量库，结构化数据（金额、日期、地区）适合进数据库。关键是先分类，再决定怎么处理。"

## 四、Excel 的信息在结构里

**如果粗暴转成文本，丢掉的不只是格式**：

```
原始 Excel：
┌────────┬────────┬────────┐
│ 地区    │ 产品    │ 销售额  │
├────────┼────────┼────────┤
│ 华东    │ 产品A   │ 120万  │
│ 华南    │ 产品B   │ 95万   │
│ 华北    │ 产品A   │ 88万   │
└────────┴────────┴────────┘

粗暴转文本：
"地区 产品 销售额 华东 产品A 120万 华南 产品B 95万 华北 产品A 88万"

丢失的信息：
  ❌ 行列对应关系（华东对应的是产品A还是产品B？）
  ❌ 表头位置（哪一行是表头？）
  ❌ 数据边界（哪些是数据行？哪些是合计行？备注行？）
```

**结构一丢，Agent 就分不清：华东？华南？还是全国汇总？**

## 五、适合进向量库：💥语义信息

**这类信息找的是解释，不是算数，所以适合向量检索**：

| 信息类型 | 示例 | 用户典型问题 |
|---------|------|------------|
| sheet 名称 | "2026年Q1销售明细" | "这个表统计的是什么时间段？" |
| 表格标题 | "华东区月度销售汇总" | "这个表覆盖哪些地区？" |
| 字段说明 | "销售额=含税收入-退款" | "销售额字段是什么意思？" |
| 业务口径 | "统计口径：已发货已确认收入" | "这个表的统计口径是什么？" |
| 备注信息 | "3月下降因春节假期" | "备注里有没有说明原因？" |
| 异常说明 | "2月数据异常因系统故障" | "2月为什么突然下降？" |
| 统计规则 | "同比增长率=（本期-同期）/同期" | "增长率怎么算的？" |
| 指标解释 | "GMV 含未支付订单" | "GMV 和销售额的区别？" |

## 六、不建议直接进向量库：💥结构化数据

**这类问题的目标不是"找相关"，而是拿到"精确结果"**：

| 数据类型 | 示例 | 用户典型问题 |
|---------|------|------------|
| 订单明细 | 订单号、产品、金额、日期 | "最近一笔订单是什么？" |
| 销售流水 | 日期、地区、产品、销售额 | "3 月华东区销售额多少？" |
| 库存数量 | 产品、仓库、库存量 | "产品A 库存还有多少？" |
| 金额字段 | 单价、数量、总额 | "哪个产品单价最高？" |
| 日期字段 | 订单日期、发货日期 | "最近一周有多少订单？" |
| 地区字段 | 华东、华南、华北 | "华东区总销售额多少？" |

**处理方式**：存入数据库（SQLite/MySQL）或 DataFrame，用 SQL/Pandas 做筛选、统计、排序、计算。

```python
# 用户问："哪个产品销售额最高？"
# 正确做法：SQL 查询
SELECT product, SUM(sales) as total
FROM sales_data
GROUP BY product
ORDER BY total DESC
LIMIT 1

# 错误做法：向量检索
# → 检索到几行"相关"数据，但不知道哪个最高
```

## 七、先解析 Excel，而不是直接切 chunk

**一个 Excel 里经常不止一张表**：

```
Sheet 1: 明细数据    → 结构化数据，进数据库
Sheet 2: 汇总数据    → 结构化数据，进数据库
Sheet 3: 字段说明    → 语义信息，进向量库
Sheet 4: 备注分析    → 语义信息，进向量库
```

**核心判断：说明型还是数据型？**

```python
import openpyxl

def classify_sheet(sheet):
    """判断 sheet 是说明型还是数据型"""
    # 如果大部分单元格是文本，且没有明显的数值列 → 说明型
    # 如果有表头 + 多行数值数据 → 数据型
    text_cells = 0
    numeric_cells = 0
    for row in sheet.iter_rows():
        for cell in row:
            if isinstance(cell.value, (int, float)):
                numeric_cells += 1
            elif isinstance(cell.value, str) and cell.value.strip():
                text_cells += 1

    if numeric_cells > text_cells * 2:
        return "data"      # 数据型 → 进数据库
    else:
        return "semantic"  # 说明型 → 进向量库
```

**如果把明细和汇总混在一起，Agent 后面就容易混着用。**

## 八、识别表格区域：先找对表头和数据边界

**业务 Excel 前几行可能不是数据**：

```
行 1: "2026年第一季度销售报表"        ← 标题行
行 2: "编制单位：大麦网"              ← 说明行
行 3: ""                              ← 空行
行 4: 地区 | 产品 | 销售额 | 同比     ← 表头行
行 5: 华东 | 产品A | 120万 | +15%     ← 数据行开始
行 6: 华南 | 产品B | 95万  | -8%
...
行 30: 合计 | — | 580万 | +5%         ← 合计行
行 31: "备注：3月数据暂未统计"         ← 备注行
```

**要分清楚这些边界**：

| 边界 | 怎么识别 | 为什么重要 |
|------|---------|-----------|
| 说明行 | 前几行，没有对应表头 | 不是数据，不能当数据行处理 |
| 表头行 | 第一行有多个非空文本单元格 | 表头识别错，后面的检索、计算都错 |
| 数据行 | 从表头行之后开始 | 正确的数据起始位置 |
| 合计行 | 包含"合计"、"总计"等关键词 | 不能和明细数据混在一起 |
| 备注行 | 数据区域之后的文本行 | 语义信息，适合进向量库 |

```python
def find_table boundaries(sheet):
    """识别表格边界"""
    header_row = None
    data_start = None
    data_end = None

    for i, row in enumerate(sheet.iter_rows()):
        # 找表头：第一个有多个非空单元格的行
        non_empty = [cell for cell in row if cell.value is not None]
        if header_row is None and len(non_empty) >= 3:
            header_row = i
            data_start = i + 1
            continue

        # 找数据结束：遇到合计行、备注行或空行
        if data_start and data_end is None:
            first_cell = str(row[0].value) if row[0].value else ""
            if "合计" in first_cell or "总计" in first_cell or len(non_empty) == 0:
                data_end = i

    return header_row, data_start, data_end
```

## 九、向量块要带上下文，不是拼单元格

```
❌ 错误做法：把每个单元格独立成 chunk
  chunk_001: "华东"
  chunk_002: "产品A"
  chunk_003: "120万"
  → Agent 检索到"120万"，不知道是哪个地区、哪个产品

✅ 正确做法：保留行级别的上下文
  chunk_001: "华东区 产品A 销售额 120万 同比增长15%"
  → Agent 检索到这条，知道是华东区产品A的数据
```

**有上下文的文本块，才是对 Agent 有价值的向量块**。

```python
def row_to_text(row, headers):
    """把一行数据转成有上下文的文本"""
    parts = []
    for header, value in zip(headers, row):
        if value is not None:
            parts.append(f"{header}: {value}")
    return "，".join(parts)

# 效果：
# 原始行：["华东", "产品A", 1200000, 0.15]
# 转换后："地区: 华东，产品: 产品A，销售额: 1200000，同比增长: 15%"
```

## 十、给每个向量块加 metadata

**metadata 至少要有**：

```python
chunk.metadata = {
    "file_name": "2026Q1销售报表.xlsx",
    "sheet_name": "明细数据",
    "table_name": "华东区月度销售汇总",
    "row_range": "5-30",           # 数据行范围
    "columns": ["地区", "产品", "销售额", "同比增长"],
    "data_types": {"销售额": "number", "同比增长": "percent"},
    "time_range": "2026-01 ~ 2026-03",
    "source_type": "semantic"      # semantic / data
}
```

**真正进入向量库的不是整张表，而是**：

| 内容 | 是否进向量库 | 说明 |
|------|------------|------|
| 字段说明 | ✅ | 用户会问"这个字段是什么意思" |
| 业务规则 | ✅ | 用户会问"统计口径是什么" |
| 异常说明 | ✅ | 用户会问"为什么下降" |
| 表格摘要 | ✅ | 一段文字概括表格内容 |
| 备注分析 | ✅ | 备注信息是语义内容 |
| 少量样例 | ✅ | 2-3 行代表性数据，让 Agent 知道表长什么样 |
| 全部明细数据 | ❌ | 进数据库，用 SQL 查询 |

## 十一、提问时：Agent 先做问题路由

**真正可用的 Excel RAG = 语义检索 + 结构化计算 + Agent 路由**

```
用户问题
  │
  ▼
Agent 路由（判断问题类型）
  │
  ├─ 语义类 → 向量检索（字段说明、口径、备注）
  │   "销售额字段是什么意思？"
  │   "统计口径是什么？"
  │   "备注里有没有说明原因？"
  │
  ├─ 计算类 → 结构化查询（SQL/DataFrame）
  │   "哪个产品销售额最高？"
  │   "3 月华东区销售额多少？"
  │   "同比增长率是多少？"
  │
  └─ 混合类 → 先计算，再检索说明
      "3 月华东区为什么下降？"
      → 先 SQL 查出 3 月华东区数据和环比
      → 再向量检索备注/异常说明
      → 综合回答
```

```python
def route_excel_question(question: str) -> str:
    """判断 Excel 问题类型"""
    # 计算类关键词
    calc_keywords = ["最高", "最低", "多少", "总数", "平均", "增长率", "排名", "对比"]
    # 语义类关键词
    semantic_keywords = ["什么意思", "口径", "备注", "说明", "原因", "规则", "定义"]

    if any(kw in question for kw in calc_keywords):
        return "calculation"   # → SQL 查询
    elif any(kw in question for kw in semantic_keywords):
        return "semantic"      # → 向量检索
    else:
        return "hybrid"        # → 先计算再检索
```

**面试话术**：
> "Excel RAG 的核心是 Agent 问题路由。语义类问题（字段说明、口径、备注）走向量检索，计算类问题（最高、最低、总数）走结构化查询，混合类问题（为什么下降）先计算再检索说明。Agent 先判断问题类型，再选择合适的检索方式。"

## 十二、完整处理流程

```
Excel 文件
  │
  ▼
解析 Excel（openpyxl / pandas）
  │
  ├─ 按 sheet 分类
  │   ├─ 说明型 sheet → 提取语义信息
  │   └─ 数据型 sheet → 识别表头 + 数据边界
  │
  ├─ 语义信息 → 切 chunk → 加 metadata → Embedding → 向量库
  │   （字段说明、业务规则、备注、异常说明、表格摘要）
  │
  └─ 结构化数据 → 转 DataFrame → 写入数据库（SQLite/MySQL）
      （明细数据、金额、日期、地区、产品）
  │
  ▼
Agent 路由
  ├─ 语义类 → 向量检索
  ├─ 计算类 → SQL 查询
  └─ 混合类 → 先计算再检索
```

## 十三、💥总结

```
1. 该进向量库的是解释性信息：字段说明、口径、备注、异常原因
2. 该进数据库的是明细数据：金额、日期、地区、产品、订单流水
3. 该交给 Agent 的，是判断这次问题到底查说明还是算结果
4. 遇到"为什么下降"，要先算清楚，再去找原因说明
5. 不要整表硬塞，要保留结构、上下文和 metadata
```

**金句🎯**：

> "**没有拆分，RAG 就会猜；拆对结构，Agent 才能稳定回答。**"

**面试话术**：

> "**Excel 数据处理的核心是分类：① ❇️语义信息进向量库，② ❇️结构化数据进数据库，③ ❇️Agent 做问题路由。**
>
> **语义信息包括字段说明、业务口径、备注、异常原因，适合向量检索。**
>
> **结构化数据包括金额、日期、地区、产品明细，适合 SQL 查询。**
>
> **Agent 先判断问题类型，再选择检索方式。**
>
> **遇到混合类问题（为什么下降），先 SQL 算出数据，再向量检索说明，综合回答。关键是不要把整张表拍扁进向量库，要保留结构、上下文和 metadata。**"

## 十五、面试高频问题

| 问题 | 回答要点 |
|------|---------|
| RAG 怎么处理 Excel 数据？ | 分类处理：语义信息进向量库，结构化数据进数据库，Agent 做路由 |
| 为什么不能直接把 Excel 进向量库？ | 向量检索擅长"找相关"，Excel 问题经常要求"算正确"，直接拍扁丢失结构 |

| 混合类问题怎么处理？ | 先 SQL 算出数据，再向量检索说明，综合回答 |
