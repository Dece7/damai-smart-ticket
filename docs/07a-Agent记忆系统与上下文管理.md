# Agent 记忆系统与上下文管理

> AI 应用的上下文能力四维度：Context Window（看见历史）、RAG（找到知识）、Memory（保存偏好）、Prompt 组织（喂给模型）

---

## 一、大模型怎么记住上下文

**面试提问**：大模型是怎么记住上下文的？

💥**优质回答**💥：
> 短期靠上下文查看、长对话靠摘要压缩、长期偏好靠外部记忆、专业知识靠 RAG。

---

## 二、Agent 记忆系统三大类

### 1. 上下文记忆（Context Memory）

```
原理：把最近 N 条消息直接塞进 prompt
```

| 特点 | 说明 |
|------|------|
| 实现方式 | 滑动窗口，取最近 N 条 |
| 优点 | 简单、不需要额外 LLM 调用 |
| 缺点 | 占 token，N 太大成本高，N 太小丢上下文 |
| 适用 | 短对话（5-20 轮） |

**本项目实现**：

```python
def get_history(self, conversation_id: int, max_messages: int = 20) -> list[dict]:
    """获取对话历史（最近 N 条）"""
    messages = (
        db.query(Message)
        .filter(Message.conversation_id == conversation_id)
        .order_by(Message.id.desc())
        .limit(max_messages)
        .all()
    )
    return [{"role": m.role, "content": m.content} for m in reversed(messages)]
```

### 2. 摘要记忆（Summary Memory）

```
原理：对话太长时，用 LLM 把早期对话压缩成摘要
```

| 特点 | 说明 |
|------|------|
| 实现方式 | 每 N 轮对话触发一次摘要，用摘要替代原始消息 |
| 优点 | 省 token，长对话不丢关键信息 |
| 缺点 | 摘要会丢失细节，需要额外 LLM 调用 |
| 适用 | 长对话（20+ 轮） |

**本项目**：未实现，当前对话轮次不多不需要。

### 3. 长期记忆（Long-term Memory）

```
原理：把重要信息提取出来存到外部存储，跨会话复用
```

| 特点 | 说明 |
|------|------|
| 实现方式 | 用户画像、偏好、关键事实存数据库 |
| 优点 | 跨会话记住用户，个性化回答 |
| 缺点 | 需要信息提取和更新机制 |
| 适用 | 多轮多会话场景 |

**本项目**：未实现，当前单用户场景不需要。

### 三者组合使用

```
prompt = 长期记忆（用户画像）+ 摘要记忆（早期对话摘要）+ 上下文记忆（最近 N 条）+ RAG 检索结果
```

## 三、上下文管理四种手段

**面试提问**：真实业务里怎么做上下文管理？

**优质回答**：
> 1. 保留最近几轮对话（上下文记忆）
> 2. 更早对话做摘要（摘要记忆）
> 3. 专业知识走 RAG
> 4. 长期偏好单独存储（长期记忆）

| 手段 | 解决什么 | 实现方式 | 成本 |
|------|---------|---------|------|
| 最近几轮对话 | 短期上下文 | 滑动窗口取 N 条 | 低 |
| 更早对话摘要 | 长对话不丢信息 | LLM 压缩成摘要 | 中 |
| RAG 检索 | 专业知识 | 向量 + BM25 混合检索 | 中 |
| 长期偏好存储 | 个性化 | 用户画像存数据库 | 低 |

## 四、AI 应用的上下文能力四维度

| 能力 | 解决什么 | 你项目 |
|------|---------|--------|
| **Context Window** | 看见历史信息的能力 | ✅ 滑动窗口 20 条 |
| **RAG** | 找到外部知识的能力 | ✅ 知识库检索 |
| **Memory** | 保存长期偏好的能力 | ❌ 没有（当前不需要） |
| **Prompt 组织** | 怎么喂给大模型的能力 | ✅ System Prompt + 检索结果格式化 |

**Prompt 组织展开**：包括 System Prompt 设计、上下文排列顺序、检索结果格式化、指令约束等。

## 五、易混淆知识点

### 上下文记忆 ≠ 训练

| 维度 | 上下文记忆 | 训练/Fine-tuning |
|------|-----------|-----------------|
| 改不改模型参数 | ❌ 不改 | ✅ 改 |
| 持久性 | 临时的，会话结束就丢 | 永久的，改变模型能力 |
| 实现方式 | prompt 里塞消息 | 梯度更新模型权重 |
| 成本 | 低（只占 token） | 高（需要 GPU + 数据） |

**面试时能说出这个区别就很加分**。

### 上下文窗口 ≠ 记忆

| 概念 | 说明 |
|------|------|
| 上下文窗口 | 模型能"看见"的文本范围（技术限制） |
| 记忆 | 系统"记住"信息的能力（工程设计） |

上下文窗口是模型的硬限制（如 128K token），记忆是通过工程手段在窗口内外管理信息。

## 六、本项目记忆系统现状

```
prompt = 最近 20 条消息（上下文记忆）+ RAG 检索结果（专业知识）
```

| 层次 | 机制 | 状态 |
|------|------|------|
| 上下文记忆 | `get_history(max_messages=20)` | ✅ 有 |
| 摘要记忆 | 对话超过 N 条时 LLM 压缩 | ❌ 没有 |
| 长期记忆 | 用户画像、偏好存储 | ❌ 没有 |
| RAG 知识库 | 混合检索 + Parent-Child | ✅ 有 |

**为什么没做完备**：当前对话轮次不多，滑动窗口够用。加摘要多一次 LLM 调用，加长期记忆需要用户画像提取机制，投入产出比不高。

**面试话术**：
> "**项目实现了上下文记忆和 RAG 两层。长对话场景可以加摘要压缩，多用户场景可以加长期记忆存用户偏好。当前对话轮次不多，滑动窗口够用，不需要额外的摘要开销。**"

## 七、面试高频问题

| 问题 | 回答要点 |
|------|---------|
| 大模型怎么记住上下文？ | 短期靠上下文查看、长对话靠摘要压缩、长期偏好靠外部记忆、专业知识靠 RAG |
| Agent 记忆分几类？ | 三类：上下文记忆（滑动窗口）、摘要记忆（LLM 压缩）、长期记忆（外部存储） |
| 上下文记忆和训练的区别？ | 上下文记忆不改模型参数，临时的；训练改模型参数，永久的 |

| 怎么做个性化回答？ | 长期记忆：提取用户偏好存数据库，每次对话注入 prompt |
| 上下文窗口和记忆的区别？ | 窗口是模型硬限制，记忆是工程设计 |
| AI 应用的上下文能力有哪些？ | 四维度：Context Window、RAG、Memory、Prompt 组织 |
| prompt 太长有什么问题？ | 费用高、注意力分散、可能引入噪音，需要平衡信息量和 token 成本 |
