# AI客服购票引导功能开发记录

> AI智能客服项目的购票引导功能开发、优化和问题解决记录。

---

## 功能背景

### 1.1 需求分析

| 需求 | 说明 |
|------|------|
| 用户痛点 | 用户想买票时，需要自己查找节目、选择票档、下单 |
| AI客服价值 | 帮助用户快速找到节目，提供购票入口 |
| 安全考虑 | AI不应直接下单（风险高），应引导用户自己操作 |

### 1.2 设计思路

**行业实践**：大多数智能客服采用"引导 + 确认"模式，而非"直接执行"

**案例**：
- 手机营业厅AI客服：查询套餐 → 提供链接 → 用户自己办理
- 电商AI客服：查询商品 → 推荐链接 → 用户自己下单
- 航空AI客服：查询航班 → 提供预订链接 → 用户自己预订

**我们的方案**：
```
用户："帮我买于文文演唱会的票"
  ↓
AI调用 create_order_guide 工具
  ↓
查询节目信息 + 票档信息
  ↓
生成购票链接
  ↓
返回美观的购票卡片
  ↓
用户点击链接 → 跳转到全栈项目 → 自己完成下单
```

## 二、实现过程

### 2.1 阶段一：创建下单引导工具

**目标**：创建 `create_order_guide` 工具函数

**代码实现**：
```python
# app/chains/tools.py
@tool
def create_order_guide(program_id: int) -> dict:
    """引导用户下单，直接返回购票链接。
    
    Args:
        program_id: 节目ID
    """
    # 查询节目详情
    program = java_api.get_program_detail(program_id)
    
    # 查询票档信息
    tickets = java_api.get_ticket_categories(program_id) or []
    
    # 生成购票链接
    base_url = "http://localhost:5173"
    buy_url = f"{base_url}/contentDetail/index/{program_id}"
    
    return {
        "type": "buy_guide",
        "program_title": program.get("title", ""),
        "show_time": program.get("showTime", ""),
        "place": program.get("place", ""),
        "price_range": f"¥{tickets[0].get('price', '0')}起" if tickets else "价格待定",
        "buy_url": buy_url,
        "ticket_count": len(tickets),
    }
```

**问题与解决**：
| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 链接返回空白页 | 端口配置错误（8081 vs 5173） | 修改链接端口为5173 |
| 链接在当前窗口打开 | Markdown链接默认行为 | 使用 `<a target="_blank">` 标签 |

### 2.2 阶段二：优化AI回复格式

**目标**：让AI直接给出购票链接，而不是询问用户信息

**问题**：AI有时会询问用户地点、票档等信息，而不是直接给出链接

**原因**：系统提示词中有"节目推荐规则"，要求先获取城市信息

**解决方案**：修改系统提示词，明确说明购票意图直接给出链接

```python
# app/core/prompts.py
【订单查询规则】
3. 当用户想要购买节目时（如"帮我买xxx的票"、"有没有xxx的票"），直接使用 create_order_guide 工具，不要询问用户地点等信息。
5. 重要：当用户表达购票意图时，直接调用create_order_guide工具，不要询问城市等信息。
```

### 2.3 阶段三：优化卡片样式

**目标**：美化购票卡片，提升用户体验

**优化过程**：

**版本1：渐变紫色背景（太突兀）**
```html
<div style="background: linear-gradient(135deg, #667eea 0%, #764ba2 100%); padding: 20px;">
```

**版本2：白色背景（与米色背景混为一体）**
```html
<div style="background: white; border: 1px solid #e8e8e8; padding: 20px;">
```

**版本3：淡紫色渐变背景（最终版本）**
```html
<div style="background: linear-gradient(135deg, #667eea15 0%, #764ba215 100%); 
            border: 1px solid #667eea30; border-radius: 12px; padding: 20px;">
```

**优化对比**：
| 元素 | 优化前 | 优化后 |
|------|--------|--------|
| 背景色 | 白色（混为一体） | 淡紫色渐变 |
| 按钮文案 | 立即购票 | 前往购票 → |
| 卡片大小 | 太大太突兀 | 适中，简洁美观 |
| 边框 | 无 | 紫色半透明边框 |

### 2.4 阶段四：修复工具调用问题

**问题**：后续提问没有触发工具调用

**现象**：
- "帮我买于文文演唱会的票" → 触发工具 ✅
- "有没有周杰伦的演唱会的门票买？" → 没有触发工具 ❌

**原因**：AI没有理解后续问题也是购票意图

**解决方案**：在系统提示词中明确说明更多购票意图表达方式

```python
# app/core/prompts.py
5. 重要：当用户表达购票意图时（包括"帮我买"、"有没有票"、"想看"、"想买"等），直接调用create_order_guide工具。
```

## 四、技术要点

### 4.1 安全设计

| 设计 | 说明 |
|------|------|
| 引导而非执行 | AI不直接下单，避免误操作 |
| 用户确认 | 用户自己在页面中确认信息 |

## 六、面试话术

### 6.1 功能介绍

> "我实现了AI客服的购票引导功能。当用户说'帮我买xxx的票'时，AI会调用`create_order_guide`工具，查询节目信息和票档信息，然后生成一个美观的购票卡片，用户点击卡片可以跳转到全栈项目的详情页完成下单。"

### 6.2 设计思路

> "这个功能的设计遵循了行业实践：AI客服应该'引导'而非'执行'交易操作。直接下单风险高，容易出错，而且责任不清。所以采用引导模式，AI提供信息和链接，用户自己完成操作，这样既安全又符合用户习惯。"

### 6.3 技术亮点

> "技术实现上有几个亮点：
> 1. **安全设计**：AI不直接执行高危操作，避免误操作风险
> 2. **用户体验**：美观的购票卡片，信息一目了然
> 3. **意图识别**：支持多种购票意图表达方式
> 4. **新窗口打开**：不影响AI客服对话连续性"
